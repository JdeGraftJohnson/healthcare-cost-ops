# Dashboard Templates — Top 10 Use Cases

Each template is a self-contained pattern: a DAX measure set + a Power BI page layout + an expected business question. The library is **healthcare-anchored but domain-neutral** — every template works on any cost / volume / time / category dataset by re-pointing the spec.

UI/UX rhythm references the Microsoft Power BI sample datasets at <https://learn.microsoft.com/en-us/power-bi/create-reports/sample-datasets>. DAX patterns reference <https://learn.microsoft.com/en-us/dax/dax-syntax-reference>.

## 01 — Executive Overview

**Page layout.** Single row of KPI cards across the top (Total Spend, Total Prescriptions, $/Rx, YoY %); a single trended line below with a forward-shaded forecast band; a narrative caption block on the right with three sentences generated by Claude from the underlying numbers.

**Pattern.** All measures evaluate in the current filter context. The headline is `[Total Reimbursement]`; the trend uses `DATESYTD` for YTD framing; the YoY delta uses `SAMEPERIODLASTYEAR`.

Borrows the visual rhythm of Microsoft's **IT Spend Analysis** sample (top-of-page KPI strip + single dominant trend line).

## 02 — Top N Drug Classes (variable N + "Other" bucket)

**Question.** "Of the 1,200 drug classes, which top-N drive the visible spend, and what's everything else?"

**Pattern.** A disconnected `N` parameter table feeds `TOPN(...)`; the residual goes into an "Other" bucket via `EXCEPT` so totals reconcile. This is the canonical pattern in the DAX syntax reference for ranking with a tail.

Borrows from Microsoft's **Supplier Quality Analysis** sample (which uses TOPN + Other to show vendor concentration without overwhelming the axis).

---

## 03 — YoY Growth (time-intelligence)

**Question.** "Is this month above or below the same month last year?"

**Pattern.** A real `Date` dimension marked as date table. Two measures: `[Spend PY] = CALCULATE([Spend], SAMEPERIODLASTYEAR('Date'[Date]))` and `[YoY %] = DIVIDE([Spend] - [Spend PY], [Spend PY])`. Conditional formatting on the YoY % column (green positive when "growth = bad" is inverted in healthcare cost context — annotate this clearly in the caption).

Borrows from **Retail Analysis** sample.

---

## 04 — State Choropleth (geo + normalization)

**Question.** "Which states have the highest per-capita prescription cost?"

**Pattern.** Filled-map visual on `State`. Color = `[Spend per Capita] = DIVIDE([Total Reimbursement], RELATED(Population[Population]))`. Tooltip shows raw spend + Rx count so the viewer never confuses normalized vs absolute.

CMS SDUD includes a `Suppression Used` flag — judges must check that suppressed cells (small counts, re-identification risk) are masked in the visual, not zeroed.

---

## 05 — Cost Per Member Month (PMPM)

**Question.** "Standard healthcare normalization — cost per enrolled member per month."

**Pattern.** PMPM is the lingua franca of healthcare actuarial reporting. The measure is `DIVIDE([Total Cost], [Member Months])`. For SDUD we don't have direct enrollment counts; the spec falls back to Medicaid enrollment from KFF or CMS T-MSIS as the denominator. The template documents both formulas (PMPM and PMPY) and the judges check that the denominator source is cited in the model.

---

## 06 — Forecast Band

**Question.** "What does the next 12 months look like, with what uncertainty?"

**Pattern.** Forecasting happens **before** Power BI in `services/ingest/forecast.py` (SARIMA + Prophet ensemble), and the forecast is materialized as a Parquet table with three columns: `point`, `lo80`, `hi80`. Power BI does NOT use its built-in forecast (which is exponential-smoothing only, no exogenous regressors, no confidence-band documentation).

The visual is an area chart with two ribbons (80% and 95%) under the point forecast. A caption documents the model choice + holdout backtest MAPE. Judges (`forecast_method.py`) check that the band is shown and the methodology is disclosed.

---

## 07 — Pareto 80/20

**Question.** "Which 20% of drugs drive 80% of cost?"

**Pattern.** Two measures: `[Cumulative Spend] = CALCULATE([Spend], FILTER(ALLSELECTED('Drug'), [Rank] <= EARLIER([Rank])))` and `[Cumulative %] = DIVIDE([Cumulative Spend], CALCULATE([Spend], ALLSELECTED('Drug')))`. A combo chart shows bars (per-drug spend) + line (cumulative %); a reference line at 80% identifies the inflection drug.

Borrows directly from **Procurement Analysis** sample.

---

## 08 — Brand vs Generic Mix

**Question.** "Where could we save by substituting generic for brand?"

**Pattern.** Group NDCs by brand/generic flag from the FDA Orange Book. Two stacked bars: prescription count split, dollar split. A third measure — `[Generic Substitution Opportunity]` — flags drug classes where generic share is below the cross-class median.

This is the template most often called out in PBM (pharmacy benefit manager) analyst job descriptions.

---

## 09 — Outlier Flag (volatility-aware)

**Question.** "Which drug classes broke from their baseline this month?"

**Pattern.** ATR-style threshold (mirroring `feedback_atr_thresholds` memory): outlier when monthly change exceeds 2× the trailing 12-month standard deviation. Flag column drives a conditional-format icon. The point is **cross-class fairness** — a flat 20% threshold disadvantages volatile classes and over-flags stable ones.

Borrows from **Supplier Quality Analysis** sample.

---

## 10 — Quality Scorecard (the dashboard scoring itself)

**Question.** "Is this dashboard healthy enough to ship?"

**Pattern.** A meta-page that surfaces the judge harness output: last refresh, refresh success rate over 30 days, RLS roles present, data-source documentation completeness, judge composite score. This is the audit layer made visible to consumers — the "Submit as-is / Tighten / Re-work" verdict from `services/judges/audit_runner.py --merge` is rendered as a single banded indicator.

No MS sample analogue — this is the harness's own contribution.

## How the Claude generator uses these templates

1. The spec (`dashboard_spec.yml`) lists which templates apply.
2. `services/dax/generate.py` reads the template DAX, parameterizes it against the spec's column names, and emits the measure set as a Tabular Object Model JSON fragment.
3. The judge harness scores the result against each template's expected pattern via `services/judges/template_fit.py`.
4. The auditor (`auditors/dax_auditor.py`) re-inspects the emitted DAX against the DAX syntax reference for hallucinated functions, wrong arity, or anti-patterns.

A future dashboard for a non-healthcare domain (e.g., financial-services trading PnL) reuses templates 01–04, 06–07, 09–10 unchanged and swaps in domain-specific templates for the rest.
